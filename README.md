# TetonCounty.us

A modern community guide to Victor, Driggs, and Teton Valley, Idaho, sponsored by Teton Flats. The first release focuses on useful local discovery. Apartment lead generation is a later phase.

The initial inventory contains **426 distinct places and experiences**: 90 Victor, 204 Driggs, 43 wider-valley, and 89 explicitly labeled nearby trips. All **31 hiking-map points** from Teton Flats are included. Records are source-listed, not owner-confirmed; this is a starting market inventory, not a guarantee of completeness or current operations.

## Run locally

The site uses a small Node.js static generator with plain HTML, CSS, and JavaScript; it does not use Astro or React. Cloudflare serves prebuilt pages, while a Worker handles form requests and D1 stores the private review queue.

Use Node 22.13+ (Node 24 LTS recommended).

```sh
npm ci
npm run dev
```

Open `http://localhost:4321`. The dependency-free static builder generates the site before starting the preview. Run `npm run build` after editing templates, CSS, scripts, or data, then reload the browser. The preview saves test form submissions to ignored `.local/submissions.sqlite` and clearly labels them as local. It sends no email and does not publish data.

```sh
npm run check
```

This builds every page, runs submission integration tests using SQLite, validates listing provenance, and checks internal links and JSON-LD. Wrangler is the only development dependency; there is no browser framework or production npm dependency.

## What is included

- Photo-led, responsive homepage with locally hosted fonts and WebP assets.
- Instant directory search, town/category/season filters, empty states, and URL-persisted filters.
- Dedicated Victor, Driggs, category, trail, and individual place pages.
- Interactive, on-demand Leaflet/OpenStreetMap map using source-provided coordinates.
- Addition, correction, and contact requests, validated and saved into a private D1 review queue.
- Production Turnstile verification, same-origin checks, size limits, honeypot, and hourly rate limits.
- Canonicals, social metadata, JSON-LD, sitemap, robots.txt, `llms.txt`, full text inventory, and public JSON records.
- Transparent sponsorship, privacy text, source citations, and verification status.
- Cloudflare Worker configuration, D1 migration, and GitHub checks workflow.

## Project structure

| Path | Purpose |
| --- | --- |
| `src/templates.mjs` | Server-generated HTML and structured data |
| `src/data.mjs` | Cross-source normalization and identity merges |
| `data/*.json` | Curated inventory and reviewed aliases |
| `public/assets/app.js` | Progressive search, map, navigation, and form behavior |
| `public/assets/styles.css` | Responsive design |
| `src/worker.mjs` | Cloudflare submission API |
| `migrations/` | Private review database schema |
| `scripts/build.mjs` | Static generation, machine-readable exports, alias redirects |
| `scripts/import-*.mjs` | Repeatable public source extraction |
| `research/` | Provenance, coverage, deduplication, and unresolved source conflicts |
| `docs/PLAN.md` | Product and data roadmap |
| `docs/DEPLOYMENT.md` | GitHub and Cloudflare launch steps |
| `docs/EDITORIAL.md` | Review, publishing, source refresh, and retention workflow |

`src/listing-ids.mjs` is generated by the build so correction requests can only reference published listings. Generated `dist/`, raw research downloads, local submissions, credentials, and Wrangler state are ignored by Git.

## Launch status

Production runs on **Cloudflare Workers with Static Assets**, with `https://tetoncounty.us` as its canonical domain. Source is maintained at [monroeresidential/tetoncounty](https://github.com/monroeresidential/tetoncounty). The Worker, D1 database, initial migration, Turnstile widget, and runtime secret are configured. See [deployment operations](docs/DEPLOYMENT.md) for build settings and release steps.

Cloudflare Builds is configured for `main`, with repository access granted to the existing Cloudflare Workers & Pages GitHub App. Each push runs the build, tests, and site checks before publishing. Submissions enter a private D1 review queue. They do not send email or appear publicly until reviewed and incorporated into the source data.

The source inventory omits disputed addresses and does not invent operating hours, event dates, ratings, prices, or live trail conditions. Some source-linked websites are social pages, Maps, or trail guides rather than operator websites. Source dates describe extraction, not verification by an owner.

Core application payload at initial validation: approximately 3.4 KB JavaScript + 6.2 KB CSS, gzip. Fonts, images, and optional map assets are additional. No production Core Web Vitals or Lighthouse score is claimed before deployment.
