# Teton County

A modern community guide to Victor, Driggs, and Teton Valley, Idaho, sponsored by Teton Flats. The first release focuses on useful local discovery. Apartment lead generation is a later phase.

The current inventory contains **458 distinct places and experiences**: 111 Victor, 213 Driggs, 45 wider-valley, and 89 explicitly labeled nearby trips. All **31 hiking-map points** from Teton Flats are included. Records are source-listed, not owner-confirmed; this is a starting market inventory, not a guarantee of completeness or current operations.

The October 18 directory CSV review added 32 source-linked places and resources and enriched four existing listings. Its row-level decisions are recorded in `research/directory-csv-review.json`; the new records live in `data/curated.json` so source-import refreshes do not overwrite them. Residential subdivisions, unsupported listings, and alternate records were not bulk-published.

## Run locally

The site uses **Astro 7 + TypeScript**, with reusable Astro components and schema-validated content collections. Astro generates complete HTML pages; a small TypeScript bundle handles interactive search, maps, and forms. Cloudflare serves the prebuilt pages, while a Worker handles form requests and D1 stores the private review queue.

Use Node 24 or newer; production builds use Node 24.

```sh
npm ci
npm run dev
```

Open `http://localhost:4321`. Astro reloads changes to pages, components, styles, and browser scripts. Restart `npm run dev` after editing the curated `data/` inventory so the content collection and correction allowlist refresh together. The development server saves test form submissions to ignored `.local/submissions.sqlite` and clearly labels them as local. It sends no email and does not publish data.

`npm run build` creates production output in `dist/`. `npm run preview` serves that static output for inspection; use `npm run dev` to test the local submission API.

```sh
npm run check
```

This type-checks the Astro and TypeScript source, builds every page, runs content and submission tests, validates listing provenance, and checks internal links and JSON-LD. Astro runs at build time; visitors receive static HTML and a small browser script. Maps load only when requested.

## What is included

- Trailhead field-guide design with self-hosted Young Serif, Mulish, and Caveat fonts, pine and parchment colors, responsive AVIF/WebP photography, and matching social and app icons.
- Instant directory search, town/category/season filters, trail difficulty filters, empty states, and URL-persisted filters.
- Dedicated Victor, Driggs, category, trail, and individual place pages.
- Interactive, on-demand Leaflet/OpenStreetMap map using source-provided coordinates.
- Addition, correction, and contact requests, validated and saved into a private D1 review queue.
- Formspree inbox and email notifications, with persisted delivery status and automatic retries.
- Production Turnstile verification, same-origin checks, size limits, honeypot, and hourly rate limits.
- Canonicals, social metadata, JSON-LD, sitemap, robots.txt, `llms.txt`, full text inventory, and public JSON records.
- Transparent sponsorship, privacy text, source citations, and verification status.
- Cloudflare Worker configuration, D1 migration, and GitHub checks workflow.

## Launch status

Production runs on **Cloudflare Workers with Static Assets**, with `https://tetoncounty.us` as its canonical domain. Source is maintained at [monroeresidential/tetoncounty](https://github.com/monroeresidential/tetoncounty). The Worker, D1 database, initial migration, Turnstile widget, and runtime secret are configured. See [deployment operations](docs/DEPLOYMENT.md) for build settings and release steps.

Cloudflare Builds is configured for `main`, with repository access granted to the existing Cloudflare Workers & Pages GitHub App. Each push runs the build, tests, and site checks before publishing. Submissions enter a private D1 review queue, then go to Formspree form `meaedrjo` for inbox storage and editor email notifications. Configure `drew@monroeresidential.com` as that form's notification recipient in Formspree. Nothing appears publicly until reviewed and incorporated into the source data.

Delivery is attempted immediately after saving. A five-minute Worker cron retries temporary failures, with backoff and a maximum of eight attempts. The `submission_notifications` table records acceptance or failure separately from editorial review. Local previews never send to Formspree.

The source inventory omits disputed addresses and does not invent operating hours, event dates, ratings, prices, or live trail conditions. Some source-linked websites are social pages, Maps, or trail guides rather than operator websites. Source dates describe extraction, not verification by an owner.

Core application payload after the Trailhead redesign: approximately 3.4 KB JavaScript + 9.1 KB CSS, gzip. Fonts, images, and optional map assets are additional. Hashed Astro assets use immutable caching. These are build measurements, not production Core Web Vitals or a Lighthouse score.
